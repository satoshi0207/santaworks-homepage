## 2. 参考サイト（Satoshiさん提示・2026-08-15）

| | 何が効いているか |
|---|---|
| hta-program.jp | **縦組み見出し＋白箱**。3Dキャラが中心。右端に縦ナビ。背景は静かなグレー |
| itplus.co.jp/studio-sakana-kai | **円形に回る文字**。中心に写真コラージュ。回るスクロール印。手描きの線 |

**共通する型：**
1. タイポグラフィが主役（文字が図版になっている）
2. 中心に「見るもの」が1つある
3. 構造（ナビ・バッジ・線）が画面の要素として見えている
4. 背景の環境エフェクトはほぼ無い

→ **第1案（粒の空気を強化）はこの型と方向が違った。**第2案で構成を寄せた。

## 3-2. 🔴 スマホの見た目は同格（Satoshiさん・2026-08-15）

**「PCで作ってスマホに縮める」を禁止する。**もともと CLAUDE.md の確定事項に
「モバイルファースト：閲覧はスマホが主」とある——リニューアルでもこれを落とさない。

- **モックの段階からスマホの構図を別に設計する。**縮小ではなく組み替え：
  - 縦組み見出しは**スマホでも縦のまま**（参考のHTAもスマホで縦を保っている）
  - 光球は下に並べず、**見出しの背後・右下に半分逃がして重ねる**（奥行きとして使う）
  - 縦ナビは出さない（既存のハンバーガーに統合）
  - CTAは全幅・親指の届く高さ・タップ領域44px以上
- **確認は毎回2画面。**モック・実装のレビューは PC と 375px 幅をセットで見る。
  片方だけ見て決めない
- 性能予算（LCP 2.5秒）は**もともとモバイル基準**。実測はスマホ実機で取る

## 4. リッチ化の中身（機能側）

### 4-1. 読者が追える仕組み（Journal）

- ⬜ **RSS/Atom フィード**（`/journal/feed.xml`）。静的書き出しで生成できる。14本書いて購読手段が無いのは単純な穴
- ⬜ **テーマ絞り込み**。`posts.ts` の `theme` 2軸整理（8/2）がまだ画面に出ていない
- ⬜ **関連記事・前後の記事**（記事末尾）
- ⬜ 記事ページの共通レイアウト化（現状は1本ずつ手書きTSX。MDX化は別判断＝コスト大）

### 4-2. 受注に効く強化

- ⬜ Works の見せ方（デモ17本の一覧性・実物2商品の扱い）
- ⬜ 問い合わせ導線（ヒーローCTA→フォームの距離）
- ⬜ 制作実績としての「このサイト自体」の説明ページ（作り方を1枚書く案）

### 4-3. `/picks/`（アフィリエイト棚）

- 設計済み（`affiliate/picks-plan.md`）。**このリニューアルのデザイン層の上に実装する**
- 広告バッジ・「広告について」ページ・`lint_picks.py`・ナビに出さない——すべて picks-plan の決定のまま

## 5. 順番（提案）

**土台 → 機能 → 化粧の順。**化粧を先にやると、機能追加のたびに壊れる。

| 段 | 中身 | 理由 |
|---|---|---|
| 1 | デザイントークン整理・共通レイアウト | 後続全部の土台 |
| 2 | RSS・絞り込み・関連記事 | 機能はデザインより先に安定させる |
| 3 | **ヒーロー本実装** | モックで方向確定後 |
| 4 | Works・トップの再構成 | ヒーローとトーンを揃える |
| 5 | `/picks/` | 新デザイン層の上に。1本目の記事と同時期 |

⚠️ **Journal 記事本文の見た目は最後まで触らない。**「読ませる場所」の可読性が資産。
