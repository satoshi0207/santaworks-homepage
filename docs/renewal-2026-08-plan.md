## 2. 参考サイト（Satoshiさん提示・2026-08-15）

| | 何が効いているか |
|---|---|
| hta-program.jp | **縦組み見出し＋白箱**。3Dキャラが中心。右端に縦ナビ。背景は静かなグレー |

**共通する型：**
1. タイポグラフィが主役（文字が図版になっている）
2. 中心に「見るもの」が1つある
3. 構造（ナビ・バッジ・線）が画面の要素として見えている
4. 背景の環境エフェクトはほぼ無い

→ **第1案（粒の空気を強化）はこの型と方向が違った。**第2案で構成を寄せた。

### F 案「つくったものの壁」（2026-08-15・nob-sakuma.com を実見して翻訳）

参考: https://nob-sakuma.com/ （Satoshiさん提示）。
**構造の本質＝「主役の仕事そのものを、枠の壁にして敷き詰める」**（TVプロデューサー
だから枠がテレビで中身が番組）。実測で WebGL/canvas ゼロ・DOM と画像だけ——
性能予算内で構造を借りられることを確認した。

うちへの翻訳：**枠＝ブラウザ、中身＝つくったもの。**
デモ17本・製品画面・Journal の図版の実物スクリーンショットが斜めの壁でゆっくり流れ、
中央の白箱に見出し。**ヒーローがそのままポートフォリオになる＝受注目的に最直結。**

- 🚫 借りないもの：ポップな色・手描きフチ（トーン違い）／人の顔（ガードレール⑤）
- ⚠️ 本実装の追加コスト：スクショの撮影・軽量化（WebP・遅延読み込み）が一式必要。
  モックは色面のダミーカードで構図のみ確認できる

✅ **方向は F「つくったものの壁」で確定**（Satoshiさん・2026-08-16）。
✅ **ヒーローの実装GOも同日に出た**（「一旦コンパクトしてから実装しましょう」）。
**範囲はヒーローのみ。**他ページ・RSS・/picks/ などのGOはまだ。
モックへの往復で詰めた最終仕様（**設計図は `docs/mocks/hero-f-final-2026-08-15.html`**。
実装はこのファイルを開いて挙動を確かめながら移植する）：

| 項目 | 確定値 |
|---|---|
| 壁 | 5列×4枚×2セット（継ぎ目なしループ）。`rotate: -7deg`（スマホ -8deg） |
| カード | `clamp(280px, 24vw, 340px)`（スマホ 210px）。業種パレット16種・レイアウト4型 |
| 流れ | **常に流れ続ける**。列ごとに上り・下り交互、一周36〜57秒（列で速度差） |
| 奥行き | 中央列 scale 1.08、外側 0.92＋blur 1.7px＋減光 |
| ポインタ | 壁全体が ±22px で追従（lerp 0.055） |
| 白箱 | すりガラス。**eyebrow＋見出し＋一文＋CTA 2つのみ**。🔴 **数字の帯（サンプル数等）は置かない**（Satoshiさん・2026-08-16） |
| 登場 | カード時間差 → 0.9s後に白箱 → 2s後にSCROLL印（14秒/周） |
| その他 | ライト固定・reduced-motion で全静止・追加ライブラリ0 |

**本実装で変わるもの：**カードの中身をダミー配色 → **実物スクリーンショット**へ
（デモ17本＋商品2本。WebP化・遅延読み込み・`loading="lazy"`）。
🔴 スクショに顔・実在情報が写らないこと（ガードレール⑤⑦）。

⚠️ 参考に見た他の5案は `docs/mocks/hero-directions-cdef-2026-08-15.html`（C/D/E/F切替）と
`hero-motes-2026-08-15.html`（粒の強化版）に保存済み。経緯ごと残す。

## 3-2. 🔴 スマホの見た目は同格（Satoshiさん・2026-08-15）

**「PCで作ってスマホに縮める」を禁止する。**もともと CLAUDE.md の確定事項に
「モバイルファースト：閲覧はスマホが主」とある——リニューアルでもこれを落とさない。

- **モックの段階からスマホの構図を別に設計する。**縮小ではなく組み替え：
  - 縦組み見出しは**スマホでも縦のまま**（参考のHTAもスマホで縦を保っている）
  - 光球は下に並べず、**見出しの背後・右下に半分逃がして重ねる**（奥行きとして使う）
  - 縦ナビは出さない（既存のハンバーガーに統合）
  - CTAは全幅・親指の届く高さ・タップ領域44px以上
- **確認は毎回2画面。**モック・実装のレビューは PC と 375px 幅をセットで見る。
  片方だけ見て決めない
- 性能予算（LCP 2.5秒）は**もともとモバイル基準**。実測はスマホ実機で取る

## 4. リッチ化の中身（機能側）

### 4-1. 読者が追える仕組み（Journal）

- ⬜ **RSS/Atom フィード**（`/journal/feed.xml`）。静的書き出しで生成できる。14本書いて購読手段が無いのは単純な穴
- ⬜ **テーマ絞り込み**。`posts.ts` の `theme` 2軸整理（8/2）がまだ画面に出ていない
- ⬜ **関連記事・前後の記事**（記事末尾）
- ⬜ 記事ページの共通レイアウト化（現状は1本ずつ手書きTSX。MDX化は別判断＝コスト大）

### 4-2. 受注に効く強化

- ⬜ Works の見せ方（デモ17本の一覧性・実物2商品の扱い）
- ⬜ 問い合わせ導線（ヒーローCTA→フォームの距離）
- ⬜ 制作実績としての「このサイト自体」の説明ページ（作り方を1枚書く案）

### 4-3. `/picks/`（アフィリエイト棚）

- 設計済み（`affiliate/picks-plan.md`）。**このリニューアルのデザイン層の上に実装する**
